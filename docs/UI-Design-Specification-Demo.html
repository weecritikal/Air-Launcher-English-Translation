v1.2 MD3 融合 示例展示

本页面是规范文档的可视化示例。基于"好看的下载类界面"提炼，对照"难看的实例管理页"重构。 克制中的层次 —— 毛玻璃 + 自定义壁纸，纯色 + 圆角 + 阴影 + 边框，不使用渐变与装饰条。 v1.1 融合 ZL2 的 MD3 Expressive 实践：Surface 容器层级 · CardPosition 拼接 · JellyBounce 缓动 · 连锁进场 · Shimmer 骨架屏。 v1.2 新增：语义化颜色访问器 · 四种缓动类型 · 背景透明度联动。

✓ 规范
本示例已遵循的规范
  • · 文字用 labelColor 系列，亮色壁纸下仍清晰
  • · 图标全部带圆角容器 + 类型色背景
  • · 每张卡片右侧有 chevron 暗示可点击
  • · 选中态三层强化：1.5pt 边框 + 圆点徽章 + 轻染色
  • · 真 Bento Grid：大卡片 + 4 个快捷磁贴 + 列表
  • · 顶部"当前实例"作为视觉焦点
  • · 主操作"启动游戏"显式按钮，非长按
  • · 加载器/版本类型用彩色 pill，非纯文本
✗ 反面
原 VersionManagerViewController 问题
  • · 文字硬编码 [UIColor whiteColor]，亮色壁纸不可见
  • · 裸 SF Symbol cube.box.fill，无容器无类型色
  • · 无 chevron，用户不知可点击进设置
  • · 选中态仅 1.5pt 边框，无徽章无背景
  • · 伪 Bento：砍掉快捷磁贴后退化为两条列表
  • · 无视觉焦点，满屏列表
  • · 切换实例藏在 0.5s 长按手势里
  • · 死代码 VMQuickActionCell/VMRendererCell 未注册

MD3 Expressive 融合

v1.1 新增

借鉴 ZL2（ZalithLauncher2）Material Design 3 Expressive 实践。iOS 优先，MD3 补充 —— 毛玻璃不变、系统色不变，仅引入 Surface 容器层级、CardPosition 拼接、JellyBounce 缓动、连锁进场、Shimmer 骨架屏等增强视觉层次。

阻尼余弦模型 f(t) = 1 - 0.6·e⁻⁸ᵗ·cos(6πt)，3 个震荡周期，"果冻感"按压回弹。

左：JellyBounce（果冻回弹） · 右：Spring 0.7 阻尼（原规范 9.2）

15.12
MD3 融合决策树
新建界面是否需要 MD3 融合？
  ├─ 否 → 遵循原规范第 1-14 章
  └─ 是 → 需要哪种 MD3 元素？
           ├─ 视觉层次不足 → 用 Surface 容器层级（第 2.7 节）
           ├─ 卡片色访问混乱 → 用语义化访问器（第 15.9 节）
           ├─ 卡片拼接分组 → 用 CardPosition 拼接（第 15.2 节）
           ├─ 进场动画平淡 → 用连锁进场（第 15.3 节）
           ├─ 缓动类型单一 → 用四种缓动类型（第 15.10 节）
           ├─ 主题切换突兀 → 用遮罩动画（第 15.4 节）
           ├─ 加载态过时 → 用 Shimmer 骨架屏（第 15.5 节）
           ├─ 深色分隔弱 → 用 FakeShadow（第 15.6 节）
           ├─ 卡片标题/内容混 → 用头/身分段（第 15.7 节）
           ├─ 壁纸透出弱 → 用背景透明度联动（第 15.11 节）
           └─ 按压无弹性 → 用 JellyBounce（第 15.1 节）
✓ MD3 融合原则
  • · iOS 优先，MD3 补充
  • · 毛玻璃不变，仍叠加 BackgroundManager
  • · 系统色不变，仍用 labelColor 系列
  • · 不引入 Compose，仅借鉴设计理念
✗ MD3 融合禁止
  • · 用纯色替代毛玻璃
  • · 引入 MD3 onSurface 替代 labelColor
  • · 强制旧界面重构采用 MD3 元素
  • · 同一界面混用超过 3 个 Surface 层级
